1. Qué vamos a verificar

El DUT es rtl/sync_fifo.sv: una FIFO síncrona (First-In, First-Out). Es una cola de datos donde lo primero que entra es lo primero que sale.

Parámetros y señales

  • WIDTH=8: cada dato tiene 8 bits (0–255).
  • DEPTH=16: caben 16 datos (potencia de dos).
  • wr_en, wr_data: escritura.
  • rd_en, rd_data: lectura.
  • full, empty: flags de estado.
  • Reset asíncrono, activo en bajo.

Reglas clave

  • Lectura FWFT (first-word-fall-through): rd_data siempre muestra el dato más antiguo mientras no esté vacía.
  • Los punteros tienen un bit extra para distinguir full de empty.
  • Se escribe solo si wr_en && !full.
  • Se saca solo si rd_en && !empty (evaluado antes del flanco).
  • Escribir con full o leer con empty se ignora.
  • Lectura+escritura simultánea está permitida: con full solo cuenta la lectura; con empty solo cuenta la escritura.

4. Cómo corre una prueba

UVM ejecuta fases en orden. Haz clic en cada paso.

build_phase

Se construye la topología: el test crea el fifo_env, el env crea el fifo_agent y el fifo_scoreboard, y el agent crea driver, sequencer y monitor. Todo se registra con uvm_component_utils.

connect_phase

Se conectan los canales TLM: el driver pide items al sequencer, el monitor publica en ap hacia el scoreboard y hacia coverage. Sin conexiones, los datos no llegan a nadie.

run_phase

Aquí ocurre la simulación: la secuencia genera items, el driver maneja el interface, el monitor muestrea cada ciclo y el scoreboard compara contra su cola de referencia. El reloj es de 100 MHz.

check_phase

El scoreboard revisa que no queden errores pendientes: flags full/empty correctos, dato FWFT correcto y conteo de intentos de overflow/underflow. Cualquier discrepancia es un uvm_error.

report_phase

UVM imprime el resumen: número de errores, warnings y el reporte de cobertura de fifo_coverage. Si hay errores, el test falla.

5. Tests y cobertura

fifo_smoke_test

Prueba mínima: escribe y lee algunos datos. Verifica que el camino básico funciona y que el testbench arranca bien.

fifo_fill_drain_test

Llena la FIFO hasta full y la vacía hasta empty. Prueba los flags en los extremos y el orden FIFO completo.

fifo_overflow_underflow_test

Intenta escribir con full y leer con empty. Comprueba que esas operaciones se ignoran y que los contadores del scoreboard suben.

fifo_simul_test

Lectura y escritura en el mismo ciclo. Verifica la regla: con full solo saca, con empty solo escribe.

fifo_random_test

Secuencia aleatoria con pesos sobre wr_en y rd_en. Busca esquinas que los tests dirigidos no cubren.

fifo_coverage

Covergroups de wr_en x rd_en x full x empty y bins de ocupación. Mide qué combinaciones ya se ejercitaron.

7. Qué aprendiste / conceptos clave

DUT

El diseño bajo prueba. Aquí: la FIFO síncrona.

Sequence / Item

Un item = un ciclo de reloj con wr_en,rd_en, wr_data y los valores observados full, empty, rd_data. La secuencia es la lista de items.

Driver

Traduce items a señales del interface usando el clocking block drv_cb.

Monitor

Observa el interface con mon_cb y publica items por ap; los resets van por rst_ap.

Scoreboard

Modelo de referencia (cola SV) que predice el comportamiento y compara con lo observado.

Coverage

Mide qué combinaciones de estímulo/estado se ejercitaron realmente.

8. Ejercicios guiados

Ejercicio 1 — Llenar y comprobar que la escritura 17 se ignora

Escribe una secuencia dirigida que llene la FIFO (16 escrituras) y luego intente una escritura más. Comprueba que full está a 1 y que el intento se ignora.

Pista

Usa repeat(16) con wr_en=1 y rd_en=0. Después pon wr_en=1 un ciclo más y mira full y el contador de overflow del scoreboard.

Solución 
task body();
  repeat (16) begin
    req = fifo_item::type_id::create("req");
    req.wr_en = 1; req.rd_en = 0; req.wr_data = $urandom_range(0,255);
    start_item(req); finish_item(req);
  end
  // 17ª escritura: debe ignorarse porque full=1
  req = fifo_item::type_id::create("req");
  req.wr_en = 1; req.rd_en = 0; req.wr_data = 8'hAA;
  start_item(req); finish_item(req);
endtask

Ejercicio 2 — ¿Por qué con full solo saca la lectura?

Explica por qué en un ciclo simultáneo de lectura y escritura estando full=1 solo tiene efecto la lectura.

Pista

Piensa en la condición de escritura: wr_en && !full. Si full=1, esa condición es falsa aunque wr_en=1.

Solución

La escritura solo ocurre si wr_en && !full. Con full=1 la escritura queda bloqueada, pero la lectura sí cumple rd_en && !empty, así que la FIFO se vacía una posición. El resultado neto es que la ocupación baja en 1. Simétricamente, con empty=1 solo cuenta la escritura.

Ejercicio 3 — Añadir un bin de transición de ocupación

Añade a fifo_coverage un bin que cubra la transición de ocupación de 15 a 16 (llegar a full desde casi lleno).

Pista

Puedes muestrear count y usar bins trans o guardar el valor anterior en una variable auxiliar.

Solución 
covergroup cg_occ with function sample(int c);
  cp_count: coverpoint c {
    bins low  = {[0:7]};
    bins high = {[8:15]};
    bins full_bin = {16};
    bins trans_15_16 = (15 => 16);
  }
endgroup
